## メンバーの追加・削除

1. https://github.com/kentng111/mysite/settings/access を開く
2. 「Add people」→ 相手の GitHub ユーザー名を入力して招待
3. 相手にメールの招待を承認してもらう
4. 手順書 [02](02_新しいPCのセットアップ.md) を渡す

削除は同じ画面で「Remove」。

## 「内容がぶつかった」ときの直し方

`git-push.bat` / `get-latest.bat` は `git pull --rebase --autostash` を使っています。ぶつかると、取り込み途中の状態で止まります。そのPCで PowerShell を開き、`mysite` フォルダで作業します。

```powershell
cd $HOME\myApp\mysite
git status
```

### A. いったん元に戻す（安全）

```powershell
git rebase --abort
git stash list     # 「autostash」が残っていれば次を実行
git stash pop
```

これで、ぶつかる前の状態（自分の変更あり・最新は未取得）に戻ります。そのうえで、ぶつかったページを手作業で整理してから、もう一度 `git-push.bat` を実行します。

### B. その場で解消する

1. `git status` で「both modified」になっているファイルを開く
2. `<<<<<<<` 〜 `=======` 〜 `>>>>>>>` で囲まれた部分を、正しい内容に書き直す（記号の行は消す）
3. 次を実行

```powershell
git add -A
git rebase --continue
```

4. `git-push.bat` で公開

## 公開した内容を取り消す

```powershell
git log --oneline -10          # 戻したい更新の番号（左の7文字）を確認
git revert 番号                # その更新を打ち消す更新を作る
git push
```

数分で公開サイトも元に戻ります。

## Hugo のバージョンを上げる

1. 各PCで新しいバージョンを入れ、`preview_local.bat` で表示崩れがないか確認
2. `.github/workflows/deploy.yml` の `hugo-version` を同じ値に変更して公開
3. 手順書 01・02 のバージョン表記を更新

> `"latest"` にはしないでください。Hugo の更新で、ある日突然公開に失敗する原因になります。
